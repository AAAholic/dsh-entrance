# 从角色线索形成一幅作品

本文只用于用户主动提出的 DIY；普通安装沿用随包宵宫作品。入口见 [SKILL.md](https://github.com/AAAholic/dsh-entrance/blob/main/SKILL.md)。以下是创作判断依据，不是固定答案、必填流程或另一份审批表。

## 理解角色，保留联想空间

研究应改变画面选择。根据本次需要了解外形、性格习惯、身份环境、关联形象和用户偏好，挑出能转化为视觉的线索即可。已有合格素材和明确方向时直接深化；只换图、换色或修一处细节时遵守原范围。

区分事实、二创演绎和自己的提案。原作事实应有可靠来源，OC 以用户设定为准；新的场景、组合或文案可以自由设计，并按创作提案说明。不必要求普通背景、配色或每件装饰都有官方出处；视觉上的呼应可以成为组合理由，但不能借此虚构专属关系、官方地点或原作台词。

用户未指定的偏好不是默认偏好。方向开放时，可以比较少量在活动、空间、图形语言或观看关系上有实质区别的方案，再根据用户要求、现有素材和制作能力选择。把选择标为本次设计判断，不照搬案例中的场景或替用户声称喜欢某一面。

## 让画面自己表达

人物、环境、装饰、文字和动作应形成能直接看见的关系。可以从服饰结构、角色习惯、世界中的造型语言、配角关系或配色展开；选择有用的线索，不要求所有特点都出现，也不排斥已有合理视觉方向。研究更全面，不代表必须全部推翻上一版。

先想整幅画面的主次、空间或有意采用的平面构成，再决定需要什么素材。不要从“扇子换成什么、鱼换成什么”开始填槽。普通衬托元素可以保留；重要装饰如果既无清晰的构图作用，也看不出与选定方向的关系，应重新设计或移除。抽象图形不必承担可被一眼识别的象征含义。

优先围绕用户已有的合格素材构思。需要新素材时，比较身份准确性、姿态、画风、完成度、构图适配和使用条件。素材与构思可以相互调整，不能为了方便制作悄悄取消明确要求。

复杂建筑或场景的完成度必须与人物匹配。代码图形可用于合适的几何构成、纹样和动效，但“像某座城市”“象征某种身份”不等于视觉成立。若粗糙图形无法支撑目标风格，换合适素材、绘图路线或经用户意图允许的设计方向。

## 留下最少的制作依据

一小段策划记录即可，按实际需要组织：

- 用户要求与沿用素材；未指定但由执行者选择的部分。
- 关键线索及来源，选定方向和主要取舍。
- 人物、环境、文字和动作怎样共同表达；还缺什么素材。
- 当前预览、待解决问题，以及技术和视觉检查结果。

不按候选数量、文档长度或设定条数衡量创作。需要澄清的只有会实质改变结果的关键缺口；普通构图判断可在已有授权范围内继续。

## 制作、观察、修正

先检查独立素材，再看静态全图。按实际显示尺寸判断画风、细节、空间、主次和可读性；深浅底与局部放大用于检查具体疑点。场景若采用写实空间，要有可信的站立、悬挂或前后关系；平面拼贴则要有清晰的图形组织，而非无意漂浮。

静态成立后接入分层登场与水波退出，播放完整过程并检查宽窄窗口。构图或素材有问题就回到相应环节；技术检查与解释文字不能抵消可见缺陷。具体接入见 [模板指南](TEMPLATE-GUIDE.md)，素材标准见 [素材规格](ASSET-SPEC.md)，证据范围见 [验收标准](ACCEPTANCE.md)。

## 宵宫案例的来路

随包作品来自维护者与 Codex 的多轮协作：参考研究、人物候选比较、图像生成/编辑、分层实现及实际预览共同形成结果。维护者参与了主题与候选选择，这不等于智能体已独立验证同样的创作能力。

人物与表情经过图像工具生成/编辑；鱼饰与飘带使用过维护者提供的参考图进行提取和重绘。最后结合折扇、水纹、烟花及动作节奏形成祭典画面。这里既有前景提取，也有修补和重绘，不能统称为无损抠图；参考素材的权利不会因生成或编辑自动转移。

保留实际素材来源、处理方式与版本，公开使用时遵守 [LICENSE-ASSETS](../LICENSE-ASSETS) 和 [NOTICE](../NOTICE.md)。历史技术验证范围见 [验证历史](VERIFICATION-HISTORY.md)，三轮独立创作试用见 [试用记录](AGENT-TRIAL.md)。
