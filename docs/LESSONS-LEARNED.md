# 实现过程中遇到的问题

以下总结来自本地扩展的代码、决策记录和验证报告。它记录可复用的原因与处理方式，不把早期测试结果当作当前发布版的验收。历史证据范围见 [VERIFICATION-HISTORY.md](VERIFICATION-HISTORY.md)。

## 画面与分镜

| 问题 | 处理与可复用原则 |
| --- | --- |
| 只在完整壁纸上增加粒子，仍没有“人物登场” | 把欢迎阶段拆成背景、屏风、折扇、人物、文案、前景；工作台仍使用其自己的背景。先设计各层进入顺序。 |
| 烟花像等大的放射线，且都挤在上方 | 区分菊花、垂柳、牡丹、掌形、锦冠的轨迹和拖尾，错开爆点高度、半径、时间；确定性种子便于逐版比较。 |
| 装饰越来越多却没有层次 | 保留大块轮廓，细节降低对比；人物和标题在烟花之上。不要只增加粒子数来解决构图问题。 |
| 波纹更密，却仍像机械条纹 | 增加独立圆心、错位组、前后遮挡和明暗差，不只增加同一组的线数。 |
| 桌面看着合适，窄窗里红屏、飘带与标题挤在一起 | 竖屏使用自己的锚点和比例；顶部固定的飘带不能跟着整个构图偏移。使用实际视口检查，不只看设计图。 |
| 有三条鱼，但轮流短暂出现时看起来仍只有一条 | “对象数量”和“常态可见数量”不是一个指标。让多条鱼的弧线跳跃窗口错峰重叠，用多个时间点检查可见数量；水平来回游不符合本版分镜。 |
| 手部旋转后关节出现断缝 | 身体挖空区与运动补片留出重叠；旋转中心放在腕、肘关节。提高幅度后重新检查最极端角度。 |
| 表情贴图破坏原脸，或加载失败留下空块 | 表情只覆盖局部眼嘴，允许完全省略表情素材；主图失败释放模态，装饰失败则降级。 |
| 飘带整张摆动，顶端也在漂 | 外层只负责入场定位，内部按高度递增位移并延迟相位。顶端位移严格为零，尾端才有明显摆动。 |
| 飘带切条形变出现横线、接缝或半透明变暗 | 采样片段略重叠封缝，同时使用互不重叠、对齐像素的裁切区，每个半透明像素只画一次。 |
| 左束或角色的幅度增加后被原裁切框切掉 | 参数范围变化也改变空间需求；边距、局部缓冲、关节裁切要一起检查，不能只把乘数翻倍。 |

## 性能与合成

| 问题 | 处理与证据边界 |
| --- | --- |
| 首次播放卡，第二次却比较顺 | 提前显式 `decode()`，缓存成功的图像；真实蒙版图层以非零低透明度经历绘制后再启动时钟。失败 Promise 从缓存移除，允许重试。不能据此声称所有 GPU 已预热。 |
| 每帧旋转大幅 SVG 图像导致多次栅格化 | 把手掌、小臂、眼嘴拆成小 SVG 裁切岛，移动外层 HTML；保留静态图像让合成器复用。 |
| Retina 下透明全屏 Canvas 过大 | 用 CSS 尺寸绘制，限制 backing-store 像素比和总像素量。水波约 120 万、烟花约 60 万，飘带约 30 万；按模块单独控制。 |
| 没退出就分配大水纹缓冲 | 水纹从 `1 × 1` 开始，第一个有效帧再分配；关闭烟花或强度为零时也避免分配大缓冲。 |
| 退场同时做全屏模糊和水波，增加合成负担 | 取消工作台动态模糊，保留轻微垂直浮起。水体用多层低透明度宽色带表现柔和边缘。 |
| 每帧读取容器尺寸，造成不必要的布局工作 | `ResizeObserver` 缓存尺寸，绘制函数消费缓存。尺寸改变时同步更新画布与绘制参数。 |
| 欢迎主动画结束后仍一直重绘 | 主时间轴完成即停止；只有开启的局部环境动作继续。后台显式暂停它们，卸载取消 RAF 和监听器。 |
| 把 `display:none` 的“预绘制”当成真实准备 | 不可见节点可能不走实际栅格化路径。准备阶段使用非零低透明度真实层，同时为基础加载设置超时。 |
| 准备阶段开启“减少动态”后画面仍然很淡 | 切换静止模式时恢复 `opacity`、清掉预热背景与计数，并直接渲染完成构图；单独覆盖该边界。 |
| 旧透明效果偶发出现黑块 | 早期工作壁纸的 WebGL `alpha:false` 产生不透明黑底，依赖 `screen` 混合隐藏。后续修复透明输出；当前入场改用透明 Canvas 2D。旧机制的修复不等于已证明原生偶发闪烁永久消失。 |

## 退出与宿主生命周期

| 问题 | 处理与可复用原则 |
| --- | --- |
| 欢迎图先没了，水纹还独自播放 | 水体与场景遮罩共享几何和 `2200 ms` 时钟，三道波前逐步擦除原图，取消独立整图淡出和尾波。 |
| 用于退出的点击触发了工作台按钮 | 捕获并消费退出手势全序列；按住指针超过视觉结束仍保留输入屏障，直到释放及其 click 被消费。 |
| 按键退出后，长按重复字符进入输入框 | 消费的键码集合跨越欢迎节点生命周期，直到对应 `keyup`；失焦/后台时清掉中断状态。 |
| 重播、卸载或异步加载晚到，又启动旧动画 | 每个异步回调先检查 `disposed`；统一释放入口清理旧场景、超时、观察器和临时工作台动画。 |
| 模态已关，焦点丢到 body 或被错误抢回 | 挂载前保存焦点；对 dialog 设可访问名称；退出只恢复仍连接且合理的原节点。 |
| Shadow DOM 内按钮发起重播，退出后没回到该按钮 | `document.activeElement` 只给出 host；递归读取 `shadowRoot.activeElement` 保存真正的内部控件。同时只在设置面板确实打开时执行关闭后的焦点恢复，防止重复关闭把旧焦点重新抢回。 |
| 正在工作时，慢加载的欢迎突然弹出来 | 加载期间已发生用户工作输入，就跳过本轮自动播放；已有宿主启动弹窗优先。手动重播保持独立。 |
| 宿主玻璃弹窗样式误作用于全屏欢迎 | 为欢迎 host 明确声明无背景模糊和阴影，独立不透明绘制。不要改动所有宿主弹窗来修一个欢迎页。 |
| 上游宠物中注入的 CSS 被宿主覆盖，提示文字挤动角色 | 上游记录确认过这类环境行为；关键 host 定位要稳定，内部样式放自己的 Shadow DOM。显示状态不要让内联 `display:none` 与类名规则相互矛盾。 |
| 服务端改完、禁用再启用却仍是旧逻辑 | Node ESM 同 URL 缓存可能保留旧模块，服务端更改需要重启相关宿主进程；纯资源/客户端刷新路径与它分开。 |
| 源码改了，安装版或构建产物没更新 | 修改源模块后重新构建，检查生成物新鲜度；分别核对源码、包内文件、已安装文件和实际运行窗口。 |

## 设置与发布

| 问题 | 处理与可复用原则 |
| --- | --- |
| 滑块能拖动但没有对应效果 | 每个控件都对应明确的渲染参数，并用零值、默认、中点、最大值检查实际画面；移除没有消费者的旧控件。 |
| 欢迎开关意外改变工作壁纸 | 欢迎与壁纸分离为独立偏好域和视图；预设只修改自己负责的字段。独立插件只保留欢迎字段。 |
| 扩大新上限后旧用户效果突然增强 | 用 schema 版本迁移实际含义；新中点代表旧默认，而不是简单修改 UI 标签。局部幅度与速度分别可调。 |
| 面板很长，恢复默认和预览被挤出屏幕 | 只滚动设置主体，把操作区保留可见；在窄窗口实际用键盘、鼠标检查。 |
| 改了图片，用户仍看到旧图 | 素材采用 `immutable` 缓存时必须换文件名或版本目录；可变索引不能照搬同一缓存策略。 |
| 独立插件仍依赖原来的皮肤或资源路由 | 检查 import、URL、localStorage、事件名和 DOM 选择器，全部明确所有权；从干净宿主安装一次。 |
| 预览所有文件都存在，却返回 `403` | 预览服务器的根路径若保留尾斜杠，再拼 `sep` 就可能生成 `//` 前缀；合法解析路径不匹配。先 `resolve()` 规范化根目录，再做目录边界检查，不删除路径守卫来绕过错误。 |
| 关闭欢迎后整个设置面板都灰掉 | 共享设置视图把 `getStatus().active` 解释为控制器可用性；独立控制器误把它设成“当前有欢迎层”。拆为 `active: !disposed` 与 `sceneActive: Boolean(intro)`，没有欢迎时仍可调参数。 |
| 隔离预览正常，真实 DSH 中 `ctx.slots` 不可访问 | Cordis 的上下文服务需要声明依赖。客户端补 `export const inject = ['slots']`；Node half 对应声明 `['webServer']`。必须通过真实 boot 加载 bundle，直接导入 controller 的预览不会触及这个错误。 |
| 插件停用或依赖移除后，控制器/资源路由仍残留 | 官方 Cordis `4.0.4` 将普通 `export function apply` 走可构造路径，返回 disposer 不等于注册了清理，`ctx.on('dispose')` 也不是当前 fiber 回收方式。两端使用 `ctx.effect(() => dispose, label)` 托管幂等清理；真实 Cordis 检查依赖缺失、注入/移除/恢复、fiber 停用与路由重启。 |
| 发布包漏掉资源目录 | `package.json.files`、导出、构建产物和压缩包实际内容一起检查。开发目录正常不代表安装包完整。 |
| 把整份私人工程上传作为“开源” | 从明确文件清单提取插件，保留必要许可证；排除本地路径、状态、令牌、聊天截图、个人配置、依赖缓存和原始会话记录。 |
| 把演示角色素材也直接称为 MIT | 代码许可和图像/角色权利分别记录。本包 PNG 明确排除在 MIT 代码许可外并说明非官方二创范围；改造和再发布时使用有权使用的素材。 |

## 验证结论如何写

“构建通过”“浏览器行为通过”“原生窗口观察通过”“严格帧率测量”“用户喜欢这个效果”是不同结论。它们相互补充，不能替代。

“使用真实宿主库”也要写清替身范围。本项目 Cordis 生命周期检查使用官方 `4.0.4`，但客户端 DOM/React 是测试替身；因此它证明资源归属与清理，不能证明设置真实渲染。后者由实际浏览器的独立检查覆盖。

对于无法复现的间歇问题，写清已经排除的机制和未覆盖的条件。保留失败样本与旧版本证据，后续修复创建新报告，不覆盖旧结果。不要用更容易通过的新阈值解释原失败。

## 用 Git 保留可学习的演进

独立仓库的首次提交应明确标注为从已有工程提取的基线，而不是伪造之前的开发历史。之后按可审阅的变化提交，例如宿主适配、参数迁移、鱼群、手部/飘带控制、验证与文档。

提交说明记录具体问题、行为变化及运行过的检查。非平凡设计用短决策记录解释取舍。发布标签对应可安装的代码和验证摘要；发现缺陷后提交修复，保留旧标签的真实状态。

历史原生截图可能包含工作内容，因此本仓库只整理机制和必要的脱敏结论，不复制私人工作区截图或完整对话记录。
