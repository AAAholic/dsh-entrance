# 创作验收：看实际产物，记录证据边界

用于用户的个性化作品。技术可用、视觉合格、用户喜欢分别记录；当前案例的历史检查范围见 [验证历史](VERIFICATION-HISTORY.md)，不能直接继承为新作品结果。

## 观察什么

| 对象 | 合格底线 | 优秀参考 | 实际证据 |
| --- | --- | --- | --- |
| 人物素材 | 指定特征完整；独立叠合主体的透明背景有效，无明显误删/底色残留；约定的画框式呈现按其画幅边界检查 | 边缘或画框与场景自然衔接，角色特征稳定 | 原图/结果对照及目标背景预览；透明主体另查深浅底，详见 [素材规格](ASSET-SPEC.md) |
| 构图 | 人物识别区域、文案和进入提示不被意外遮挡；裁切符合用户意图 | 主次清晰，留白与装饰有关系，视线与图层引导自然 | 目标宽屏、矮窗、窄窗截图，记录实际尺寸 |
| 风格 | 人物、背景、文案、装饰协调，文字可读 | 颜色明暗、形状与装饰密度支持用户所选情绪 | 场景全图与具体问题位置；无需保留示例所有装饰 |
| 入场与停留 | 图层出现有先后，人物落位稳定；需要的局部动作不出现裂缝、穿插或截断 | 动作幅度与节奏服务人物表达，装饰不持续抢夺注意力 | 一次完整播放；有局部动作时检查极值帧和重复周期 |
| 水波交接 | 水波与画面擦除同步，结束后工作台正常显示和操作 | 交接连续，残影、突变与停顿不干扰体验 | 从点击到恢复操作的完整观察；检查不同点击起点 |
| 可复现交付 | 资源路径可用，源码与生成物对应，能从交付工程重新打开 | 新环境无需作者解释即可复现，限制交代清楚 | 基线、修改清单、命令与结果、输出位置 |

“优秀”用于指导改进，不是要求无限放大后所有像素都无瑕疵。先用实际显示尺寸判断影响，再放大具体疑点。不要自行用数字评分代替缺失的视觉证据。

## 公共交互检查

按改动影响选择检查，并在新作品中保留以下公共约束：

- 用户触发退出后，点击或按键不落到工作台；特别检查长按超过视觉退出时长再释放。
- 退出后工作台可用；从设置重播后，焦点回到合适控件。
- 减少动态保留可理解的静态画面；后台暂停，卸载后监听器、动画和临时节点被清理。
- 主图缺失、可选素材缺失或加载过慢时不永久阻挡工作台。
- 新素材的首次加载与重播分别观察；只跑重播不能说明冷启动表现。

现有 `npm run test:browser` 包含“三条鱼”“飘带”“默认挥手设置”等宵宫案例断言。修改对应能力时，应将这些断言替换为新作品的可观察要求，并记录原因；保留退出、输入保护、焦点与生命周期验证。未修改案例时直接运行原检查。命令与平台差异见 [平台适配](PLATFORM-GUIDE.md)。

## 证据能支持什么

| 实际完成的工作 | 可以报告 | 不能推断 |
| --- | --- | --- |
| 读取文件、检查透明度/尺寸 | 文件结构与参数有效 | 抠图干净、构图美观 |
| 构建与单元检查 | 对应代码检查通过 | 浏览器显示或原生宿主正常 |
| 浏览器截图和行为检查 | 此浏览器/视口的显示与交互结果 | 原生 DSH、另一操作系统或严格帧率 |
| 原生 DSH 观察 | 该平台、宿主版本与安装包的实际结果 | 未检查的系统、设备和版本 |
| 用户确认 | 用户对展示版本的反馈 | 其他版本或其他用户的偏好 |

没有能力观察某一层时，明确写“未验证”及原因。截图中有问题时不能只引用自动化通过；自动化失败也不能靠主观好看来覆盖。

## 最小交付记录

随作品提供一份简短记录，格式不限，包含：

- **任务与基线**：角色/风格、保留与允许改变的范围、仓库提交或版本、操作系统和相关运行环境。
- **产物**：素材、源码、生成物与预览位置；修改了哪些文件，哪些公共机制有改动及原因。
- **素材处理**：来源、抠图/修边/生成等实际做法，保留原貌的对照；不把生成重绘称为无损提取。
- **验收**：检查对象、命令或观察方式、结果及截图/报告位置。按“通过 / 失败 / 未验证 / 不适用”记录，不把未验证写成通过。
- **限制与下一步**：剩余问题、可行方案、用户已接受的限制；没有用户确认的限制不要代其接受。

达到本次约定的合格标准即可交付。若必要步骤缺工具、越过用户允许的修改范围或无法核验，说明具体阻碍并完成其他独立工作。素材发布许可与个人预览分开核对，不把代码 MIT 当成图像授权。
