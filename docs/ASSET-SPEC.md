# 素材结果标准：供执行智能体判断与验收

本文规定素材需要达到的结果与检查证据，具体做法由执行智能体结合当前环境、已有技能与用户要求选择。
适用于 v1.0.1 参考工程；示例中的人物和装饰只是案例，不限定新角色、OC 的姿态或风格。

## 先确定这次要保留什么

从用户请求、原图和已有记录提取以下边界；已有答案直接沿用，不重复询问。

- 使用场景与构图：半身或全身、主体位置、预期窗口范围，以及文字和装饰的主次。
- 原貌约束：必须保留的脸、发型、服饰、饰品与姿态；哪些内容允许改变。
- 编辑范围：仅蒙版和排版，或已允许边缘修色、补全、重绘；不要把后几项统称为“抠图”。
- 动作要求：用户明确要求的动作与可选效果分别记录；不能因素材困难自行取消明确要求。

用户已有素材时从该素材开始。缺少关键边界且会影响原貌时再澄清；普通布局选择可以提出有依据的方案。
未获准改变原貌时，保留原图内容；如必须补全才能完成需求，说明缺失区域、预期改动与可行路径。

完整创作先用 [创作流程中的策划卡](CREATIVE-WORKFLOW.md) 确定场景，再形成素材需求：`要表达的特点 → 画面职责 → 所需表情/姿态/视角/图层 → 候选与取舍`。参考研究与初步看图可以交叉进行，但正式选图应能说明它如何支持场景；不能只凭“这张漂亮”决定整幅作品。已有合格原图是设计条件，优先围绕它构思，不因研究步骤而强制换图。

## 先有合格角色，再处理透明背景

人物素材以实际取得的合适二创、原创图片为主，优先沿用用户提供的合格原图。只有角色名时，先取得并查看对应造型的视觉参考，再筛选可用于本次任务的图片；按构图、清晰度、完整度、画风和使用条件选择，不以搜索排名代替判断。参考图与最终素材的来源分别记录；搜到图片不等于已经取得使用或公开分发许可。OC 以用户设定为依据，没有既定形象时可用绘图能力按描述创作并明确仍需确认的设计选择，不虚构“原作形象”。

先看独立主体与参考/设定的对照，再看透明度和场景：检查适用的脸部、发型或整体剪影、服饰结构、关键配件、比例、姿态和约定画风。黑发、红眼、女仆装等标签相同，不足以证明是同一个角色；非人形 OC 按自身结构与辨识特征检查。已有原图只需抠图时，不应重新设计人物。

**禁止用代码拼画角色来替代人物素材。**不能把手写 SVG/CSS/Canvas 人形或几何拼图光栅化后，当作完成了角色绘制。文件格式不是判断依据：取得的现成矢量原画仍属于素材；限制的是以现场代码拼画代替角色素材获取或绘图的路线。代码可以用于合成、布局、动画、交互，也可制作河流、波带等简单元素，但后者必须通过下文的视觉门禁。不能把人物改称“装饰”来绕过这条边界。

陪衬角色、吉祥物或有既定形象的伙伴也按角色素材标准处理；它们体积小或被放在装饰层，不构成代码拼画的例外。视觉呼应可以成为选用理由，但不能据此虚构专属关系或官方设定。

可以使用 image 类绘图/编辑能力生成或处理素材，但它是需要验收的制作路线。以选定参考的表现目标和完成度为基准，检查身份稳定、肢体或部件结构、服饰衔接、线条与材质的一致性；在实际显示尺寸看整体，放大查看脸部和关键细节。不能出现明显的结构错误、粘连、意外缺损或未完成的草图感，也不能未经允许改变原图内容。简洁画风仍需造型准确、边缘与细节完成，不能用“风格化”解释失真。

主体不合格时先定位差异：局部错误可修正，整体造型失真或当前能力不足时更换素材或制作路线。只有工具成功提示、文字特征清单或自述“风格化重绘”时，不能判为视觉通过。缺能力时依照本文末尾的方案报告缺口；布局占位需明确标注，角色任务保持未完成。

## 透明人物：合格与优秀

以下标准用于需要独立叠合的人物。若用户意图允许保留原背景并采用画框式呈现，按约定画幅与整体构图验收；这种路线不能称为透明人物素材已经完成，也不能替代用户明确要求的抠图。

| 观察项 | 合格 | 优秀所增加的质量 |
| --- | --- | --- |
| 透明性 | 有实际透明通道，目标背景能透出；不是白底或绘制的棋盘格 | 半透明发丝、薄纱等在明暗背景上自然衔接 |
| 完整性 | 指定主体和辨识特征保留，没有明显误删或未经允许的补画 | 细小饰品、发梢和轮廓细节也稳定保留 |
| 边缘 | 实际显示尺寸下，背景残留、色边和锯齿不明显干扰观看 | 不同背景下仍干净，柔硬边缘符合原图表现 |
| 构图 | 人物清晰、比例正常，裁切与遮挡符合本次意图 | 主体、留白、文字与装饰关系自然，宽窄窗口都协调 |

合格是交付门槛，优秀是继续改善的方向。不要要求完美像素，也不要仅靠无限放大后的瑕疵决定返工。
先判断异常是否违背原图和使用意图，再决定是否修复：

- **负空间不是误删孔洞**：手臂与身体、发束之间的空隙可能本来就应透明；对照原图确认。皮肤或衣服中新增的透明区域才可能是误删。
- **半身裁切不是意外截断**：原定半身下沿可以保留并安排遮挡；新出现的断指、缺发、饰品截断需要修正。不要自动补成全身。
- **半透明不是背景残留**：薄纱、发丝、光效可能需要部分透明；判断其在目标背景上的表现，不强制二值化。
- **抠图不是补全**：蒙版只能决定已有内容的可见性，不能恢复原图中被遮住或画幅外的内容。补绘须符合已确定的编辑范围。

## 必须留下的实际证据

1. 原图与处理结果对照，能确认人物特征及本次修改范围。
2. 文件尺寸、有效透明度检查结果；同时查看浅色、深色和目标背景上的预览。
3. 按实际显示尺寸查看完整构图；对疑点做局部检查后，再回到正常观看尺寸判断影响。
4. 在约定的宽窄窗口和最大动作幅度下，检查清晰度、裁切、遮挡、接缝与位置。
5. 记录已发现的问题、处理结果或尚未解决的限制，以及证据对应的素材版本。

测量透明度与观察视觉效果分别报告：存在 alpha 不证明轮廓正确，缩略图好看也不证明文件透明。
静态预览不能替代动作检查，浏览器预览不能证明 DSH 原生表现。未能检查的环境明确标为未验证，不推断所有设备均通过。
素材合格、工程检查通过与用户审美认可分别记录；不要互相替代。

## 装饰、表情和局部动作

完整主题迁移依据选定场景列出所需元素与职责，再做模板取舍：`场景需要 → 依据与表达方式 → 所需素材/图形 → 对应图层及旧元素去留`。覆盖占据画面的大背景、前景、纹样与主要装饰即可，不要求填满每个装饰槽。依据来自用户偏好、角色设定或选定视觉方向，不能从名字、发色或一个属性擅自推导整套风格，也不按旧模板已有的物件数量决定新场景。

例如，屏风的职责可能是承托人物和分隔明暗，折扇可能提供放射构图，飘带可能提供纵向连接；新作品可以用别的形状实现这些职责，也可以删去不需要的职责。游鱼不因改成深色、加一片鳍或改名就自动成为合适的新主题装饰。水波退出的共同几何属于交互机制，场景中的底部装饰波带则是可以重新设计的视觉元素。

先在整幅静态场景中检查新形状、纹样、材质、密度与留白是否支持所选方向；临时隐藏人物和角色名，能帮助发现旧主题是否未经判断就被沿用。它是诊断方法，不要求背景单独就能认出角色。相容元素可保留，用户只要求换人物、换色或明确沿用祭典时遵守该范围；完整迁移不能把配色替换当作全部设计工作。

装饰先明确职责：固定徽记、悬挂物、漂浮物或前后景。按实际显示大小准备，确保真实透明背景与适合的轮廓。
固定点必须与画面中的连接位置相符；例如悬挂飘带的顶端应稳定，摆动末端需留余量。新装饰不必照搬示例固定点。
检查装饰完整运动范围，避免非预期遮脸、盖字、出界，或固定点与视觉连接处分离。

### 简单代码元素的视觉门禁

河流、波带、光晕、简单纹样等可用 SVG/CSS/Canvas 实现；允许使用代码不等于默认视觉通过。以本次选定风格及实际观看效果为依据，不按代码长度或图形数量认定“简单”。复杂插画若现有能力无法达到所需质量，应使用合适图像素材或绘图能力，不靠堆叠基础形状补足。

| 门禁 | 必须实际检查 | 失败例 |
| --- | --- | --- |
| 设计适配 | 说明元素的画面职责与造型依据，查看参考或明确设计目标；确认形状、纹样、材质和颜色服务本次主题 | 旧祭典波带只改色便称为深海河流；装饰与角色画风明显脱节 |
| 静态完成度 | 查看元素局部及整幅场景，在目标宽窗、矮窗、窄窗检查轮廓、连接、渐变、层次和主次 | 可见拼接缝、意外锯齿、断裂、填色错误、出界，或大块图形抢占人物与文案 |
| 动态完成度 | 播放完整入场、停留与退出；有循环或形变时观察完整周期及极值帧，检查速度、连接和遮挡 | 跳帧式突变、接缝张开、物体变形失去原形、遮脸盖字，或与水波擦除脱节 |
| 证据与结论 | 留存本版本实际截图/录屏及发现的问题，逐项标记通过、失败、未验证或不适用；纯静态元素的循环项可不适用 | 仅凭 DOM、数学曲线、自动化通过或“应该顺滑”宣布视觉合格 |

适用项全部通过，才能纳入声称视觉完成的交付。任何项失败则修正或换实现/素材；无法观察则标为未验证，可以交付明确标注的原型，不能宣称效果合格。可在用户范围内简化或移除可选元素，但不能擅自取消明确要求。门禁由执行智能体基于实际画面完成，不强制每一步由用户批准，也不能编造截图或观察结论。

### 表情和局部动作

表情素材须与人物同画布比例、缩放和注册位置；用叠图检查眼嘴覆盖区，不要分别裁紧两张图破坏对齐。
眨眼、口型需要匹配的局部内容；不同脸型不能照搬示例遮罩。生成的表情也须检查角色特征是否变化。
挥手等局部动作需要可用的部件内容、关节位置、裁切重叠和运动余量；运动暴露的缺失区域需要适当补齐。
检查完整播放与极值姿态，确认没有露洞、双重轮廓、错误穿插或不自然的关节连接；静止时对齐不足以证明动作合格。

**当前工程限制**：人物逻辑坐标、腕/肘枢轴、裁切与表情区域仍按示例姿态设置。幅度设为零只停止旋转，原裁切仍存在。
v1.0.1 尚无通用静态人物模式或主题包加载器。不同人物可能需要修改角色模块，不能声称任意 PNG 可直接替换。
可选动作可以按素材能力提出取舍；用户明确要求的动作若暂时做不到，应报告缺口并提出方案，不能把静态替代称为完成。

## 尺寸与逻辑坐标

| 素材 | 本参考工程的规格 | 使用原则 |
| --- | --- | --- |
| 人物 | `1122 × 1402`，作为逻辑坐标基准 | 保留轮廓与动作余量；不同姿态需要重新标定 |
| 表情 | 当前也是 `1122 × 1402`，局部取用眼嘴 | 与人物注册位置一致，建议同源像素规格 |
| 独立装饰 | 鱼饰 `1536 × 1024`，飘带 `724 × 2172` | 依据显示大小、比例与固定点准备 |

这些是选定素材形成的参考规格，不是所有主题的固定标准，也不是经过通用性能优化得出的像素要求。
以最大预期窗口下的实际图片显示尺寸为起点，考虑目标屏幕 DPR：

```text
源图尺寸的参考目标 ≈ 实际显示尺寸（CSS 像素）× DPR
```

`object-fit: contain` 的图片可能小于容器，应按实际绘制尺寸计算，并考虑窄屏与动作缩放。DPR 见 [MDN 说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)。
源图像素与逻辑坐标可以不同：注册位置一致、同比例的高清人物可映射回原逻辑画布；坐标含义见 [viewBox 说明](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/viewBox)。
单纯放大旧 PNG 或增大绘制缓冲不会恢复缺失细节。优化文件大小时比较实际画质，避免损伤主体或透明边缘。

## 文件体积与预览交付

先区分**原始素材、供查看的缩小预览、运行时资源、导出的整段动画**。人物 PNG 能正常使用，不代表同画面导出的动图也小；动图体积过大不能直接归因于人物图。保留原图与高质量母版，对独立副本处理，不用低清预览覆盖正式素材。

1. **定位实际限制。**记录出错步骤、原始错误、文件字节数、像素尺寸、格式/透明度；动画另记帧数与时长。核对限制来自上传文件、解码像素/内存、工具响应、编码器还是展示端；文件字节数与解码后的占用不同。没有查到的限额标为未知，不编造统一的 MB 门槛。
2. **按用途处理。**仅查看受限时制作注明用途的缩小预览，关键脸部与透明边缘另看原图局部。运行时资源按实际显示尺寸和 DPR 优化并复核 alpha，不把透明人物改成无透明的格式。保持角色逻辑坐标与注册位置，避免为缩小文件破坏动作标定。
3. **按动画格式选择策略。**多帧无损 APNG 即使启用优化仍可能很大，不能承诺单靠“再压缩”解决。用小样比较导出尺寸、帧率与编码选项；GIF 的调色板、抖动和帧间处理会影响体积及画质，不照搬固定配方。格式能力可查 [MDN 图像格式指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types)，使用 Pillow 时参考其 [动画编码说明](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)。在用户要求和接收端支持范围内选择 GIF、APNG、动画 WebP 或视频；明确指定的格式做不到时说明差距，不能把静帧或别的格式冒称为已满足。
4. **回读交付文件。**检查实际体积、尺寸、总时长、入场/停留/退出关键阶段、颜色、透明、残影与循环衔接，再在目标展示端播放。合并相同帧后帧数可能变化，应结合每帧延迟和总时长判断；降低预览帧率不能偷改作品时序。必要时另附高质量关键帧，缩小的动图不替代素材边缘验收。

记录少量有意义的参数尝试及结果；继续降低质量仍达不到限制时，换交付策略或报告限制，不无限重试。缺少编码工具或 Python 包时先按 [平台指南](PLATFORM-GUIDE.md#工具找不到或-python-缺包) 核对实际运行环境；环境缺失与文件过大分别诊断。以上是按需处理，不要求每个作品额外安装图像工具或导出所有格式。

## 能力不足时如何继续

先核对当前环境中实际可用的技能与操作，再选择方法；不要预设用户安装了某个插件，也不要把文档存在当作能力已可调用。
遇到缺口时报告：已完成的结果、缺失能力、未验证环节，以及对明确需求的影响。
从实际可访问的技能或项目一手文档核实解决路径，给出入口和适用条件；区分“已验证可操作”与“文档支持、当前环境尚未验证”。
若路径涉及额外安装、外部处理或改变原貌，按用户已授权的范围推进；范围不明时说明具体需要决定的事项，不自行替换目标。
能够独立完成的检查继续进行；下一步超出编辑边界或缺少必要能力时，停止该步骤并保留已完成结果。
达到合格标准并完成用户明确需求后即可交付；保留原图、衍生版本、来源与编辑记录，发布时使用有权分发的素材。

代码替换位置见 [模板替换教程](TEMPLATE-GUIDE.md)，整体流程见 [通用工作流](CREATIVE-WORKFLOW.md)，素材使用边界见 [素材说明](ASSETS-LICENSE.md)。
