# 换成你自己的入场模板

本文面向执行修改的开发者或智能体，以 **v1.0.1 参考工程**为基线。可使用喜欢的角色、原创角色（OC）或其他主体；先按素材能力选择实现方式，不按角色名称或性别套模板。

当前工程没有通用主题 schema、主题导入器或自动人物绑定。以下是源码适配流程，不是现成的换图按钮。先读 [通用创作流程](CREATIVE-WORKFLOW.md)、[素材规格](ASSET-SPEC.md)；命令见 [macOS / Windows 指南](PLATFORM-GUIDE.md)。

## 先确定素材能做什么

记录主体是半身/全身、宽/窄轮廓、正面/侧面、朝向、是否完整、真实透明度，以及是否有可对齐的表情或局部分层。保留原图；在深浅底色上检查发丝、衣物透明区和抠图边缘。普通壁纸不天然包含被遮挡的身体部分。

| 素材能力 | 首选实现 | 不应承诺 |
| --- | --- | --- |
| 单张完整透明主体，无局部分层 | 适配完整静态人物，保留整层入场 | 任意图片自动挥手、眨眼 |
| 非透明图片 | 需要独立叠合时先抠图；也可按用户意图明确采用保留原背景的画框式构图 | 保留背景等于完成透明素材 |
| 原定半身或有意保留的画幅边界 | 按原构图安排下沿与前景，不默认补成全身 | 所有截断都需要补图 |
| 意外缺损或严重遮挡 | 判断对目标的影响，换素材或在允许范围内补全 | 抠图能恢复缺失肢体 |
| 有对齐表情帧、可独立运动的局部 | 静态构图通过后，再标定裁切与枢轴 | 直接套用示例人物坐标 |

宽窄轮廓、半身与全身要分别安排缩放、锚点、前景遮挡和窄屏位置；不要把任意主体挤进当前人物框。镜像可能反转服装细节与文字，应先检查而非默认处理。

## 当前工程的替换地图

下列路径均相对仓库根目录；先核对实际源码，版本升级后不要只按旧行号修改。

| 文件/入口 | 当前绑定内容 | 替换时的责任 |
| --- | --- | --- |
| `lib/assets/entrance/20261006/` | `yoimiya-welcome.png`、`yoimiya-expression.png`、`festival-ribbon-v1.png`、`koi-emblem-v1.png` | 建立自己的素材目录、保留来源；主体和表情保持相同注册位置 |
| `lib/client/welcome-scene.mjs` 的 `ASSET_BASE`、各 URL、`prepareWelcomeAssets()` | 四张图的地址、加载与缓存 | 同步新 URL 和实际必需资源；取消不用的表情/装饰加载，保留失败退出 |
| 同文件的 CSS、markup、`render(t)` | 当前布局、文案、颜色和分层进入 | 适配宽屏/窄屏构图与无障碍文案；保留分镜先后关系 |
| `lib/client/welcome-character.mjs` | 1122×1402 逻辑画布、腕肘、手臂/手掌裁切、眼嘴覆盖区 | 选择真正静态路径，或为新素材重新标定 |
| `lib/client/welcome-ornaments.mjs` | 扇、红屏、底部波带及花纹的 SVG | 按主题换轮廓与配色；这些不是四张 PNG 的一部分 |
| `lib/client/welcome-ribbon.mjs` | 顶端固定、向下增强的条带形变 | 仅用于适合悬挂摆动的细长素材；其他物件可静态呈现 |
| `lib/client/welcome-river.mjs`、`welcome-fireworks.mjs` | 鱼的路径/配色、烟花配色/位置/时序 | 按风格保留、调整或移除；取消动画开关不等于移除静态鱼 |
| `lib/client/welcome-water.mjs` | 水体颜色与公共波前几何 | 配色可适配；水纹与揭幕必须继续共用 `welcomeWaterWaves()` |
| `wallpaper-preferences.mjs`、`wallpaper-settings-view.mjs`（均在 `lib/client/`） | 固定动效字段、预设和控件 | 隐藏不支持的挥手/游鱼等控件；字段含义或存储结构改变时再迁移 |

## 先完成静态适配，再决定局部动作

**将 `handAmplitude`、`handSpeed` 设为 0 只停止旋转，宵宫裁切仍存在。**`blink: false` 也只省略表情覆盖。换姿势后不能靠这三个值获得完整静态人物。

通用静态人物路径在 v1.0.1 **尚未实现**。执行者应在授权的副本中适配角色模块：用保持原比例的完整 `<img>` 呈现主体，移除旧手臂挖空与眼嘴补丁；保留场景调用所需的 `update(t)`、`dispose()` 接口和清理行为。同步素材预加载、容器比例、人物 alt 与设置控件。人物自身可以静止，人物所在图层仍随公共分镜入场。

只隐藏当前作品不支持的控件时，可保留无消费者的旧偏好字段以保持兼容，无需清空用户记录。确实改变字段含义、范围或存储结构时，再设计并检查迁移；不要为静态人物适配重写整个设置系统。

需要局部动作时，再建立该素材自己的逻辑画布、裁切路径、局部 bounds、腕肘枢轴、眼嘴区域和重叠余量。表情帧要叠图检查缩放/位置；动作需检查极值时的裂缝、重复轮廓与遮挡。仅提高同构图、同注册位置素材的分辨率，才可能保留原逻辑坐标。

## 保护公共行为

保持 `controller.mjs` 的焦点恢复、键鼠拦截、长按防穿透、后台暂停、减少动态与销毁责任；不要为一个主题重写控制器。保持主分镜 `0…2.4` 设计时间到展开时长的映射、退出冻结，以及水波与遮罩的共同几何。详见 [架构](ARCHITECTURE.md)、[分镜](STORYBOARD.md)、[水波退出](WATER-EXIT.md)。

先让主体、风格元素和文字静态构图成立，再重播检查分层关系。改源码后构建 `lib/client.js`，不要手改生成物。新素材使用自己的资源路径，不要留下源码已换而预构建客户端仍指向旧图的状态。

## 验证、许可与交付

- 按 [验收清单](ACCEPTANCE.md) 记录实际环境、命令、截图/录屏与未完成项。构建检查、单元测试、浏览器检查、原生 DSH 观察、用户审美确认是不同证据。
- `tests/entry-assets.test.mjs` 当前列出四张示例图；`scripts/verify-browser.mjs` 包含示例鱼数/控件断言。更换设计后应更新素材特定断言，保留并补齐资源失败、交互、减少动态和释放等通用检查，不能删除断言来冒充通过。
- `scripts/verify-package.mjs` 当前核对示例素材记录及五个哈希。新素材、录屏、路径或数量改变时，同步真实来源清单、哈希与对应检查；旧验收结果不能作为新素材验收。
- 代码及代码文档为 MIT；四张示例 PNG 与 `docs/media/demo.gif` 不在 MIT 范围，本仓库不授予素材权利。发布衍生版本使用有权分发的素材，参见 [LICENSE-ASSETS](../LICENSE-ASSETS)、[素材说明](ASSETS-LICENSE.md)、[NOTICE](../NOTICE.md)。
- 示例画面经 AI 生成或编辑，公开时应说明；保留原始 PNG 的 C2PA 与实际制作记录。新图片如有 AI 编辑，记录真实流程，不复制旧图片清单或伪造来源。

若另起可同时安装的插件，同步 `package.json`、`cordis.patch.yml`、两个入口的 `name`、构建脚本 ModuleLoader ID，以及 `lib/src/routes.mjs` 资源前缀、控制器存储键/事件/实例标记；重新检查并存行为。只做自己的替换版本时，先确认安装目标，避免新旧入场控制器同时启用。

交付预构建安装包或含 `lib/client.js` 的仓库，以及素材记录和验收说明。DSH 中使用真实包路径/仓库地址安装；不需要修改 DSH 主程序。打包不等于发布，安装也不等于视觉验收完成。
