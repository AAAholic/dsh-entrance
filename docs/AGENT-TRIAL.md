# 独立智能体试用与反馈

用于检查这份持续修订的指引能否让未参与开发的智能体独立接手。优先使用最新 `main` 的完整 Git 克隆；已发布的 `v1.0.1` 安装包不包含创作 Skill。命令见 [平台适配](PLATFORM-GUIDE.md)。

## 给执行智能体的起始消息

将下列消息与自己的素材、角色或 OC 描述一起交给 DS 或其他智能体；不需要附上作者的历史聊天。

> 请克隆 https://github.com/AAAholic/dsh-entrance 到新的工作目录，阅读根目录 SKILL.md，根据我提供的角色/OC 和偏好制作个人入场作品，保留分层登场与水波退场。完整创作先研究角色的性格习惯、身份环境、关联形象等特点，留下简短策划卡，选定场景后定向找素材；不要堆砌设定或只改配色。人物及配角优先用合适的二创/原创图，也可使用高质量绘图能力，严禁代码拼画角色；河流等简单元素须通过视觉门禁。先验收静态画面再接动画。已有素材和有限修改按我的范围处理；缺能力时说明并提供可行方案。交付真实预览、策划与验收记录，不覆盖现有安装或自行发布。

随消息补充你真实关心的风格、必须保留的特征和是否要求局部动作。无需为了符合模板虚构偏好；没有提供的信息由智能体合理判断，关键缺口再询问。

## 试用者记录什么

记录实际使用的仓库提交、智能体/模型、操作系统和可用工具。优先记录影响执行的事实，避免只写“很顺利”或“效果不错”。

| 项目 | 记录内容 |
| --- | --- |
| 独立理解 | 是否需要作者补充说明；补充了哪一句 |
| 研究与构思 | 发现了哪些影响设计的线索、依据是什么；比较了哪些场景方向，为什么选中或舍弃；已有明确方向时如何沿用 |
| 素材阶段 | 初始输入类型、具体返工原因、用了什么能力、哪些细节被误判 |
| 构思落实 | 选中重点分别在哪张素材、哪个构图/动作/文案中可见；是否仍从旧模板物件出发，或把设定全部塞进画面 |
| 人物与主题 | 独立主体是否符合参考/设定；背景与装饰是否经过取舍；有无把透明 PNG、特征标签或只改色当成完成 |
| 代码元素 | 河流等简单元素是否经过静态、宽窄窗与完整动态检查；有无门禁失败/未验证却宣称效果合格 |
| 工程接入 | 改了哪些文件；是否误动水波、输入保护或生成物；首次失败在哪一步 |
| 命令适配 | macOS / Windows、shell、Node 版本；失败命令和必要的错误片段 |
| 文件与交付限制 | 出错对象是原素材、查看预览、运行资源还是导出动画；真实限额/错误、体积与像素、格式选择及回读结果，是否误伤正式素材 |
| 验收可信度 | 是否实际查看图片、播放预览；有无未经检查就宣称通过 |
| 交付 | 能否从交付目录复开；还依赖哪些临时路径、工具或未保存素材 |
| 用户反馈 | 愿意保留的部分、不喜欢的具体位置；与技术问题分开 |

耗时可分为素材准备与工程接入/验证，不强求精确计时。不把人的大量救场计入“智能体独立完成”。反馈前去除令牌、私有路径和不打算公开的角色素材。

第一轮可以只做一个真实任务。后续再用不同轮廓、半身、宽主体或非人形 OC，以及不同工具条件补充试用；未运行的情形保持“未测试”。

补测时优先覆盖已经暴露的误判：只有角色名和代码工具、没有现成人物图；有合格人物图但需要完整主题迁移；绘图工具生成了细节漂亮但身份失真的人物；用户只要求换人物或换色。分别检查是否报告素材缺口而不拼画替身、是否清除不合适的旧主题残留、是否拒收身份失真的候选，以及是否遵守有限改动范围。计划答得正确只能证明指引理解；实际制作与视觉观察后，才能报告创作试用通过。

## 第三轮试用重点

本轮要验证“研究是否改变了素材与画面选择”，尚未声明试用通过。可继续使用前轮同一角色和偏好，并记录工具条件的变化，便于比较。

- 执行者是否主动发现外形之外的相关线索，并在选图前形成可解释的场景方向；来源不明的关联有无被误写成设定。
- 成片是否让选中的特点看得出来，配角与装饰是否支持同一主题；所选特点没有实际表达，或装饰削弱主题与主次时需返工。普通家具、光影等可以只做衬托，不要求每个物件都具有角色专属性。
- 是否能拒绝不合适的素材或无关特点，而非为了“全面”全收集；合格角色素材与简单代码元素门禁是否继续生效。

对 OC 或有限修改，检查是否尊重用户设定和现有合格素材，没有强制补写世界观或重新生成。试用者据实际画面反馈；策划卡写得完整与技术检查通过，均不能代替制作效果。

## 怎样据此修剪指引

优先修复阻断执行的错误、容易导致误判的标准和缺失的接入知识；删除没有改变智能体决策的重复文字。不要因为一次工具缺失就添加一整套供应商分支，也不要把一次角色特例上升为所有作品的硬规则。

试用通过说明这次环境和任务能完成。跨智能体、跨操作系统和原生 DSH 的验证范围分别记录，之后逐步扩充。
