# 第一轮独立智能体试用

用于检查这份初版指引能否让未参与开发的智能体独立接手。优先使用最新 `main` 的完整 Git 克隆；已发布的 `v1.0.1` 安装包不包含本轮新增的 Skill。命令见 [平台适配](PLATFORM-GUIDE.md)。

## 给执行智能体的起始消息

将下列消息与自己的素材、角色或 OC 描述一起交给 DS 或其他智能体；不需要附上作者的历史聊天。

> 请克隆 https://github.com/AAAholic/dsh-entrance 到新的工作目录，先阅读根目录 SKILL.md，并按需读取它指向的资料。根据我提供的角色/OC 和偏好，制作保留分层登场与水波退场的个人版本。先判断实际素材条件与可用能力，再执行。具体素材处理使用你自己已有的技能或工具；缺少能力时说明缺口并给出核实过的可行方案，继续完成不受影响的工作。保留原图和我指定的角色特征，提供可运行预览、修改清单及真实验收记录。不要覆盖我现有的安装，也不要自行公开发布。

随消息补充你真实关心的风格、必须保留的特征和是否要求局部动作。无需为了符合模板虚构偏好；没有提供的信息由智能体合理判断，关键缺口再询问。

## 试用者记录什么

记录实际使用的仓库提交、智能体/模型、操作系统和可用工具。优先记录影响执行的事实，避免只写“很顺利”或“效果不错”。

| 项目 | 记录内容 |
| --- | --- |
| 独立理解 | 是否需要作者补充说明；补充了哪一句 |
| 素材阶段 | 初始输入类型、具体返工原因、用了什么能力、哪些细节被误判 |
| 工程接入 | 改了哪些文件；是否误动水波、输入保护或生成物；首次失败在哪一步 |
| 命令适配 | macOS / Windows、shell、Node 版本；失败命令和必要的错误片段 |
| 验收可信度 | 是否实际查看图片、播放预览；有无未经检查就宣称通过 |
| 交付 | 能否从交付目录复开；还依赖哪些临时路径、工具或未保存素材 |
| 用户反馈 | 愿意保留的部分、不喜欢的具体位置；与技术问题分开 |

耗时可分为素材准备与工程接入/验证，不强求精确计时。不把人的大量救场计入“智能体独立完成”。反馈前去除令牌、私有路径和不打算公开的角色素材。

第一轮可以只做一个真实任务。后续再用不同轮廓、半身、宽主体或非人形 OC，以及不同工具条件补充试用；未运行的情形保持“未测试”。

## 怎样据此修剪指引

优先修复阻断执行的错误、容易导致误判的标准和缺失的接入知识；删除没有改变智能体决策的重复文字。不要因为一次工具缺失就添加一整套供应商分支，也不要把一次角色特例上升为所有作品的硬规则。

试用通过说明这次环境和任务能完成。跨智能体、跨操作系统和原生 DSH 的验证范围分别记录，之后逐步扩充。
