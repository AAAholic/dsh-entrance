# 怎样阅读宵宫案例

这是仓库中实际存在的参考作品。其他人物与 OC 的成功迁移仍需实践检验；下文的反例是判断示范，不是新增的已运行作品。

![宵宫案例实际浏览器演示](media/demo.gif)

演示便于观察图层与交接，不是透明边缘检查图，也不代表所有平台已验收。图像权利及 AI 编辑记录见 [素材说明](ASSETS-LICENSE.md) 与 [NOTICE](../NOTICE.md)。

## 从作品反推选择

| 案例中的选择 | 解决的问题 | 换人物时怎样判断 |
| --- | --- | --- |
| 透明人物与装饰独立成层 | 人物可以按分镜出现，装饰能放到其前后 | 先列出新场景需要独立控制的部分；一整张壁纸不能自动提供隐藏图层 |
| 人物偏右、文案偏左 | 建立两个视觉重点，保留人物轮廓 | 根据剪影、朝向和文字长度重新安排；宽大武器或翅膀可能需要更宽的人物区域 |
| 金扇、红屏、鱼饰与飘带 | 用大形状和少量细节建立祭典氛围 | 这些是风格选择，可删除或替换；不要只改颜色就声称换了完整风格 |
| 上端固定的飘带微动 | 让尾部有风感且不破坏挂点 | 同类悬挂软物可参考，刚性徽章等不能直接套用条带形变 |
| 一次手部问候与局部表情 | 人物落位后给出短暂回应 | 当前动作依赖特定姿态的裁切和注册位置。素材不足时先说明能力边界 |
| 宽屏与窄屏分别排布 | 避免把桌面构图缩小后挤在一起 | 看目标视口，检查脸、饰品、文字及提示的关系 |
| 水波和遮罩共用波前几何 | 波纹经过时真实揭开工作台 | 沿用同步机制，不能仅叠加一段水纹视频替代擦除 |

构图与时间关系见 [分镜](STORYBOARD.md)；当前代码位置见 [模板接入](TEMPLATE-GUIDE.md)。对素材质量的要求见 [素材规格](ASSET-SPEC.md)。

## 几组判断示范

这些是用于推理的对照情形，尚未附带新制作的对照图片。不要把本表当作模型已经看过图或完成验收的证据。

| 情形 | 应怎样判断与推进 |
| --- | --- |
| PNG 有透明通道，但人物外仍有白色矩形 | 文件格式成立，素材不合格；检查实际像素与预览，重新处理蒙版或换素材 |
| 发束之间有透明间隙，原图同处就是背景 | 可能是正确负空间；对照原图，不要为“补洞”把发束粘成一块 |
| 用户给的是半身 OC，下沿停在腰部 | 这是输入构图，可以利用前景或明确裁切承接；不默认补腿 |
| 预览中新增了断指，原图手指完整 | 这是处理或布局引入的缺损，应定位素材边缘、容器裁切或运动范围 |
| 换成蓝发角色后，所有祭典装饰仍保留 | 先确认用户是否就想要祭典；若要静夜氛围，调整形状、密度与明暗，而非凭发色强行决定风格 |
| 用户要求挥手，但手臂与身体重叠且没有分层 | 说明拆层/补全与标定的需求，选择可行路径；不能把完成抠图当成已经能挥手 |
| 单图人物已经漂亮地登场，用户未要求局部动作 | 可以是一份完整作品；不必为了复刻宵宫继续增加表情与关节制作 |

## 沿用什么，重新判断什么

沿用图层依次建立与水波交接的核心体验，以及输入保护、焦点、资源清理等工程机制。根据新人物重新判断布局、字体、颜色、装饰和局部动作。

`1122 × 1402`、腕肘坐标、金红色、鱼群数量与右侧人物布局都属于本案例，不是通用验收门槛。首次制作陌生角色时，记录少量决定结果的取舍和修正；实际成功后再将它补充为新案例，不预先编造迁移成果。
